## RDS とは

マネージドのリレーショナル DB です。GCP の Cloud SQL に相当します。バックアップ、パッチ、フェイルオーバー、監視を AWS が行い、こちらは SQL を使うだけです。EC2 に PostgreSQL を入れる場合と比べて運用が減り、代わりにインスタンス課金が常時発生します。

## 作るときの選択

| 項目 | 推奨 |
|---|---|
| エンジン | PostgreSQL (最新の LTS 相当) |
| インスタンス | `db.t4g.micro` / `small` から。後で変えられる (再起動を伴う) |
| ストレージ | gp3、自動拡張を有効 |
| サブネット | **プライベート** サブネットの DB サブネットグループ |
| パブリックアクセス | **無効** |
| セキュリティグループ | アプリの SG からの 5432 だけ |
| マルチ AZ | 本番は有効 (料金 2 倍)。開発は無効 |
| 自動バックアップ | 保持 7〜35 日。PITR が付く |
| 削除保護 | 本番は有効 |
| パスワード | Secrets Manager で管理 (自動ローテーション可) |

## マルチ AZ とリードレプリカ

| | マルチ AZ | リードレプリカ |
|---|---|---|
| 目的 | 可用性 (障害時の自動切替) | 読み取り性能の分散 |
| 複製 | 同期。別 AZ にスタンバイ | 非同期。数秒遅れることがある |
| アクセス | スタンバイには繋げない。障害時に同じエンドポイントが切り替わる | 別エンドポイントで SELECT を流す |
| 料金 | 2 倍 | レプリカ分追加 |

「落ちても続く」がマルチ AZ、「読みが重い」がリードレプリカ。まずマルチ AZ です。

## 接続

エンドポイント (`xxx.ap-northeast-1.rds.amazonaws.com`) と 5432 に、プライベートサブネット内の EC2 から繋ぎます。

```
DATABASE_URL=postgres://app_user:PASSWORD@xxx.ap-northeast-1.rds.amazonaws.com:5432/app?sslmode=require
```

- SSL を必須にする (`rds.force_ssl` パラメータ)
- ローカルから見たいときは踏み台経由 (SSM ポートフォワード) か、開発用 RDS を別に持つ。本番をパブリックにしない
- **IAM 認証** を使うとパスワード無しで接続できる (トークン 15 分)

## パラメータグループ

`postgresql.conf` に相当します。既定のグループは変更できないので、自分のグループを作って当てます。よく触るもの:

- `rds.force_ssl = 1`
- `log_min_duration_statement = 1000` (1 秒超のクエリをログに。遅いクエリ探しの起点)
- `shared_buffers` / `work_mem` はインスタンスサイズで既定が決まる。まず触らない

## 接続数

PostgreSQL は接続ごとにプロセスを持つので、`max_connections` は小さめ (t4g.micro で 80 程度)。

- Django / gunicorn のワーカー数 × 台数 が上限を超えないように。`CONN_MAX_AGE` で接続を使い回す
- 足りなくなったら **RDS Proxy** (接続プール) を挟む。Lambda から使うなら必須
- CloudWatch の `DatabaseConnections` を監視

## バックアップと復元

- **自動バックアップ**: 日次スナップショット + トランザクションログ。任意の時点 (PITR) に **別インスタンスとして** 復元
- **手動スナップショット**: 大きな変更 (メジャーアップグレード、破壊的マイグレーション) の前に取る
- 復元を **一度は試す**。所要時間と手順を知らないと本番で困る

## アップグレード

マイナーは自動適用 (メンテナンスウィンドウで)。メジャーは手動で、スナップショットを取ってから。事前に開発環境で動作確認。

## 監視で見るもの

`CPUUtilization`、`FreeableMemory`、`FreeStorageSpace`、`DatabaseConnections`、`ReadLatency` / `WriteLatency`。Performance Insights を有効にすると「どの SQL が重いか」が見えます (無料枠あり)。

## まとめ

- プライベートサブネット、パブリックアクセス無効、SSL 必須
- 本番はマルチ AZ + 自動バックアップ + 削除保護
- 接続数はワーカー数から逆算。足りなければ RDS Proxy
- 遅いクエリは `log_min_duration_statement` と Performance Insights

## やってみる

**ゴール:** 手元 (または無料枠) の RDS の設定を読み、遅いクエリのログを有効にする。

1. 既存の RDS があればコンソールで開き、次を確認して表にする: パブリックアクセス、サブネット (プライベートか)、SG のインバウンド送信元、マルチ AZ、バックアップ保持日数、削除保護、`rds.force_ssl`
2. 無ければ `db.t4g.micro` の PostgreSQL を **パブリックアクセス無効** で作り (無料枠)、同じ表を作る
3. パラメータグループを作って `log_min_duration_statement = 500` を設定し、インスタンスに当てて再起動
4. CloudWatch Logs に PostgreSQL のログをエクスポートし、`select pg_sleep(1)` を流してログに出ることを確認
5. 作ったものは削除 (最終スナップショットは「取らない」で)

**確認:** 設定の表が埋まり、危ない項目 (パブリック、SG が 0.0.0.0/0) が無いか判断できた。
