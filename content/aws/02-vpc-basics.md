## VPC とは

VPC (Virtual Private Cloud) は AWS 内に作る自分専用の仮想ネットワークです。CIDR (例: `10.0.0.0/16`) を決めて作ります。VPC は **リージョン** に属します。

## サブネット

VPC を AZ ごとに分割したものがサブネットです。サブネットは **1 つの AZ** に属します。

```
VPC 10.0.0.0/16
├── 10.0.0.0/24   public-1a   (AZ a)
├── 10.0.1.0/24   public-1c   (AZ c)
├── 10.0.10.0/24  private-1a  (AZ a)
└── 10.0.11.0/24  private-1c  (AZ c)
```

マルチ AZ にするため、パブリック / プライベートをそれぞれ 2 つ以上の AZ に作るのが定番です。

## ルートテーブルとゲートウェイ

サブネットが「パブリック」か「プライベート」かは、**ルートテーブル** で決まります。

| サブネット | 0.0.0.0/0 の向き先 | 意味 |
|---|---|---|
| パブリック | インターネットゲートウェイ (IGW) | 外と双方向に通信できる |
| プライベート | NAT ゲートウェイ | 外向きだけ通る。外からは入れない |
| 隔離 | (無し) | VPC 内だけ |

- **IGW**: VPC に 1 つ付ける。無料
- **NAT ゲートウェイ**: パブリックサブネットに置く。時間課金 + 転送量課金なので、不要なら作らない

Web サーバーやロードバランサはパブリック、アプリサーバーや DB はプライベートに置くのが基本形です。

## セキュリティグループとネットワーク ACL

| | セキュリティグループ | ネットワーク ACL |
|---|---|---|
| 単位 | インスタンス (ENI) | サブネット |
| 状態 | ステートフル | ステートレス |
| ルール | 許可のみ | 許可 / 拒否 |
| 既定 | すべて拒否 (インバウンド) | すべて許可 |

日常的に触るのはセキュリティグループです。「ソースに別の SG を指定する」ことができるので、「ALB の SG からだけ 80 番を許可」のように書けます。

## VPC エンドポイント

AWS のサービス (S3, DynamoDB, SSM など) にはインターネットを経由せず届く経路を作れます。

- **ゲートウェイ型**: S3 / DynamoDB のみ。無料。ルートテーブルに追加する
- **インターフェース型 (PrivateLink)**: それ以外。サブネットに ENI が作られる。有料

NAT ゲートウェイの転送量を減らしたいときにも効きます。

## まとめ

- VPC はリージョン、サブネットは AZ
- パブリック / プライベートはルートテーブルで決まる
- 外向きだけ通したいなら NAT
- SG はステートフルで許可のみ、NACL はステートレス
- S3 / DynamoDB はゲートウェイ型エンドポイント
