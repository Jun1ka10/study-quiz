## リソースで考える

URL は「もの」(名詞)、操作は HTTP メソッドで表します。

```
GET    /lessons                 一覧
GET    /lessons/{id}            1 件
POST   /attempts                作成 (回答を記録)
PATCH  /questions/{id}          部分更新
DELETE /subscriptions/{id}      削除
POST   /lessons/{id}/complete   動詞が必要な操作 (状態遷移) は サブリソース + POST
```

- `/getLesson` `/createAttempt` のような動詞 URL は避ける
- 複数形で統一。ネストは 1 段まで (`/users/{id}/attempts` は可、それ以上は平坦に)
- ID は推測できないもの (UUID) か、認可を必ず伴う

## ステータスコード

| 状況 | コード |
|---|---|
| 取得成功 | 200 |
| 作成成功 | 201 (+ `Location` ヘッダー) |
| 受け付けた (非同期処理) | 202 |
| 削除成功・本文なし | 204 |
| 入力の形が不正 | 400 / 422 |
| 未認証 | 401 |
| 権限なし | 403 (存在を隠すなら 404) |
| 無い | 404 |
| 競合 (重複作成、楽観ロック失敗) | 409 |
| レート制限 | 429 |
| サーバー側の失敗 | 500 / 503 |

「全部 200 で本文に `ok: false`」は、クライアントもログもリトライも壊します。

## エラーの形を 1 つに

```json
{
  "error": {
    "code": "validation_error",
    "message": "password must be at least 8 characters",
    "details": [{ "field": "password", "reason": "min_length" }],
    "request_id": "3f1a9c"
  }
}
```

- `code` は機械が分岐するための安定した文字列、`message` は人向け
- `request_id` を入れると問い合わせとログが繋がる
- スタックトレースや内部のテーブル名は出さない

FastAPI なら例外ハンドラで `HTTPException` と `RequestValidationError` をこの形に揃えます。

## ページネーション

一覧は必ず上限を付けます。

```
GET /attempts?limit=50&cursor=eyJpZCI6MTIzfQ
→ { "items": [...], "next_cursor": "eyJpZCI6MTc0fQ" }
```

- `offset` は件数が増えると遅く、途中で挿入があるとずれる。**カーソル** (最後の id をエンコード) が堅い
- `limit` の上限 (100 など) をサーバーで強制

## 冪等性

同じリクエストを 2 回送っても結果が 1 回分になる性質です。ネットワークは失敗し、クライアントは再送する前提で設計します。

| メソッド | 冪等か |
|---|---|
| GET / PUT / DELETE | 冪等であるべき |
| POST | 既定では冪等でない → **冪等キー** で冪等にする |

```
POST /attempts
Idempotency-Key: 7c9e6679-...
```

サーバーはキーを保存し、同じキーの 2 回目には 1 回目と同じレスポンスを返す (または 409)。オフライン同期の `client_id` はこの実装です。

## 互換性を壊さない変更

公開した API は、誰かが使っている前提で変えます。

**壊さない変更** (そのまま出してよい)

- フィールドを **追加** する
- 新しいエンドポイントを足す
- 省略可能なパラメータを足す

**壊す変更** (バージョンを上げるか、移行期間を置く)

- フィールドの削除・改名・型変更
- 必須パラメータの追加
- ステータスコードや意味の変更

クライアントは「知らないフィールドは無視する」で作ります (Pydantic の既定はそう)。

## バージョニング

- URL に入れる `/v1/lessons`: 分かりやすく、ルーティングしやすい。まずこれ
- ヘッダー: `Accept: application/vnd.app.v2+json`。URL が綺麗だが見えにくい
- 上げるのは「壊す変更」のときだけ。v1 を一定期間残し、廃止日を告知する

内部の 1 クライアント (自分のフロント) だけなら、バージョンを切らず同時デプロイでも成り立ちます。外部に公開した時点でバージョンが要ります。

## その他の作法

- **時刻は ISO 8601 の UTC** (`2026-09-03T08:00:00Z`)。ローカル時刻や epoch は混乱の元
- **ID は文字列** で返す (JS の number は 2^53 で精度が落ちる)
- **金額は整数** (最小単位) か文字列。float にしない
- **一覧のフィルタ** はクエリパラメータ (`?category=python&passed=true`)
- **OpenAPI** を正とし、そこから型とドキュメントを生成する。FastAPI は自動

## まとめ

- 名詞の URL + メソッド。状態遷移はサブリソース + POST
- ステータスを正しく使い、エラーは 1 つの形 + request_id
- 一覧はカーソルと上限。POST は冪等キー
- 追加は安全、削除・改名・必須化は壊す。壊すときだけ v2

## やってみる

**ゴール:** エラーの形を統一し、冪等キーを実装する。

1. be-06 の FastAPI に、`RequestValidationError` と `HTTPException` を `{"error": {"code", "message", "details", "request_id"}}` に整形する例外ハンドラを足す。`request_id` はミドルウェアで発行
2. `curl -i -X POST localhost:8000/items -d '{}'` で 422 の本文が新しい形になるのを確認
3. `POST /items` に `Idempotency-Key` ヘッダー対応を足す: dict にキーとレスポンスを保存し、同じキーの 2 回目は保存済みを返す
4. 同じキーで 2 回 POST し、items が 1 件のままでレスポンスが同一なことを確認
5. `GET /items?limit=2&cursor=` を実装し、`next_cursor` で 2 ページ目が取れることを確認

**確認:** エラー形式が 1 種類になった。同一キーの再送が無害になった。
