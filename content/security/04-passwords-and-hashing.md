## 保存の 3 つの選択肢

| 方式 | 漏洩したら | 判定 |
|---|---|---|
| 平文 | そのまま全員のパスワードが分かる | 論外 |
| 暗号化 (AES など) | 鍵も一緒に漏れれば全部戻る。鍵は同じサーバーにあることが多い | 不適 |
| パスワード用ハッシュ (bcrypt / argon2) | 元に戻せない。1 件ずつ総当たりするしかなく、遅いので現実的でない | これ |

ハッシュは一方向です。照合は「入力されたパスワードを同じ方法でハッシュし、保存値と比較する」で行います。**パスワードを復元する機能は作れませんし、作ってはいけません**。「パスワードを忘れた」はリセット (新しく設定) で対応します。

## なぜ SHA-256 ではだめか

SHA-256 は「速い」ように設計されています。GPU なら毎秒数十億回。漏洩したハッシュに対して、よくあるパスワード 1 億件を試すのに数秒です。

**パスワード用ハッシュは意図的に遅い** のが特徴です。

```python
import bcrypt

hashed = bcrypt.hashpw(password.encode(), bcrypt.gensalt(rounds=12))   # 保存する値
bcrypt.checkpw(password.encode(), hashed)                              # 照合 → True / False
```

- `rounds` (コスト係数) を上げるほど遅くなる。12 で 1 回 0.2〜0.3 秒。ログインには問題なく、総当たりには致命的
- ハードウェアが速くなったらコストを上げる。古いハッシュはログイン成功時に再ハッシュして移行する

argon2 (argon2id) はより新しく、メモリも消費させて GPU 攻撃に強い方式です。Django の既定は PBKDF2 ですが、設定で argon2 / bcrypt に変えられます。

## ソルト

同じパスワードを同じ方法でハッシュすると同じ値になります。すると

- 「同じハッシュのユーザーは同じパスワード」が分かる
- よくあるパスワードのハッシュを事前計算した表 (レインボーテーブル) で一気に逆引きできる

**ソルト** はユーザーごとに違う乱数で、パスワードに混ぜてからハッシュします。bcrypt / argon2 はソルトを自動生成し、出力文字列に埋め込みます (`$2b$12$<ソルト><ハッシュ>`)。自分で別の列に持つ必要はありません。

## ログイン周りの作法

- **失敗理由を区別しない**。「メールアドレスまたはパスワードが違います」。区別すると登録済みメールの列挙に使われる
- **試行回数を制限する**。IP とアカウントの両方で。一定回数でしばらく拒否 (レートリミット)
- **タイミングを揃える**。存在しないユーザーでもダミーのハッシュ照合を行い、応答時間で存在を漏らさない
- **長さの上限を極端に低くしない**。bcrypt は 72 バイトで切れるので、それ以上は事前に SHA-256 するか argon2 を使う
- **漏洩済みパスワードを弾く**。Have I Been Pwned の k-匿名 API で、既知の漏洩リストにあるものを登録時に拒否できる

## 多要素認証

パスワードは漏れる前提で、もう 1 要素 (TOTP アプリ、パスキー / WebAuthn) を足すと、パスワードだけでは入れなくなります。管理者アカウントには必須にします。

## まとめ

- 保存は bcrypt / argon2。平文も暗号化も SHA-256 も不可
- 遅さが防御。コスト係数は環境に合わせて上げていく
- ソルトはライブラリが自動で付ける
- 失敗理由は区別しない、回数制限、管理者は多要素
